# Blender をコードで回して映像にする（ヘッドレス）

実績: Blender で作った15作品（フォトリアル・トゥーン・クロス・炎・破砕・折り紙・ルービックキューブ・紙の海ほか）。数字は元の記録（`attempts.csv`・`work.json`）から。同梱: `scripts/blender_run.py`（実行して完了を待つ）・`scripts/scene_template.py`（シーン雛形）・`scripts/check360.py`（正距円筒の継ぎ目・極の確認）。**雛形は Blender 5.2.2 LTS で動作確認済み**（立方体2コマ、約5秒）。

## 初回の確認（自動）
このスキルを初めて使うときは、最初に `python scripts/doctor.py` を実行して、環境が足りているかを確かめる（足りないものと、直し方が表示される。`--fix` を付けると、直せるもの（npm install など）はその場で直す）。ユーザーに手で準備させる前に、まずこれを試す。

## 1. 実行の仕組み
- Microsoft Store 版の `blender.exe` は直接実行できない。`%LOCALAPPDATA%/Microsoft/WindowsApps/blender-launcher.exe` を使う。launcher はすぐ終了し Blender は別プロセスで動くので、**scene.py が完了ファイル（`--done`）とログ（`--log`）を書き、呼び出し側が待つ**
- `python scripts/blender_run.py scene.py [--timeout 秒] -- --out <dir> --test 0,150,299 --samples 32 --res 1920x1080`
  - 通常のインストールなら環境変数 `BLENDER_EXE`、PATH の `blender` でも同じ流れで動く
  - **scene.py は例外のときも done に `{"ok": false, "error": ...}` を書く**（書かないと待ち続ける）
- 起動は `-b --factory-startup`（設定の影響を受けない）。1コマンド10分の上限がある環境では、長い書き出しは最初からバックグラウンドで起動する（`--timeout` を長く）
- 画像は PNG 連番で `--out` に → ffmpeg で H.264（ffmpeg: libx264、crf 17〜18、`-pix_fmt yuv420p`）。PNG はエンコード後に消す

## 2. 画質の予算（必ず先に決める）
| 設定 | 実績の値 |
|---|---|
| **samples は必ず明示**（work.json／引数）。既定の128で書くと遅い | #028 は未指定で既定128 → 4.15秒/コマ（20.8分）。samples=16 に明記で 1.85秒/コマ |
| 一般的な作品（1080p） | samples 32〜64 → 0.6〜2.8 秒/コマ（#040: 32で 0.64、#044: 48で 1.98、#047: 64で 2.76） |
| フォトリアル（ガラス・水・金属） | #029: 適応サンプル最大256＋OptiX デノイズ → 7.9 秒/コマ（450コマ、59分）。下見の128で約5秒 |
| 炎・爆発（ベイクあり） | #051: ベイク（焚き火約6分・爆発約4分、キャッシュ約8GB）＋48サンプル → 6.09 秒/コマ（720コマ、88分） |
| クロス | #047: キャッシュ計算約3.5分＋約3秒/コマ（600コマ、31分） |
- 下見は 960×540・16サンプル（約0.5〜1.4 秒/コマ）。数コマ（`--test 0,中盤,最後`）に限る。全尺の書き出しは1回
- Cycles: OptiX（NVIDIA）、`use_adaptive_sampling`、`use_denoising`（OPTIX）、AgX の view transform。モーションブラー `use_motion_blur`（シャッター 0.5）
- **GPU は同時に1件**（VRAM 8GB に収まる規模にする）。GPU 待ち・利用上限の停止は制作時間に含まれるので、記録で分けて書く（#053 の下見の GPU 待ちは最後約1時間46分）
- 外部素材なしでも作れる: 手続き的に作る（絶対パスの素材に依存しない）

## 3. 手順
1. `scripts/scene_template.py` を作品用にコピー。`build()` でシーン、レンダー設定、`main()` が `--test`・`--frames a:b` を処理
2. **テスト段階でエラーを出し切る**: Blender の版で API が違う属性は例外になる（例: ライトの `visible_glossy` は未対応 #029）。`try/except` で候補を試すのは設定（look・denoiser）だけにし、シーンの構築は例外を出す
3. 下見の画像を見て、寄りすぎ・真っ暗・白っぽい霧・天井のはみ出し・飛散が速すぎ・書き出し時間、を直す（#106・#053 の実例）。**下見で直した分は試行に数えない**
4. 本番は samples を明示して1回。QC（Skill `animation-qc-selfreview`）

## 4. 失敗パターン（記録から）
- **ちらつき**（QC）: 点灯のまたたき（街灯と地面の光の輪が一緒に明滅）→ 0.4秒の立ち上がり（#028）／紙を0.42秒で裏返して白と赤の広い面が1コマで入れ替わる（#040 a01）／#040 a02（輝度変化 14.2）は ease を前半・後半に分けても星形の2コマで −6.2・−7.8 が残り、**主因は厚みの板（solidify、offset −1）どうしの食い込み**（ひれの2枚の三角形がぴったり重なり、見える面が白↔赤に急に切り替わる）。閉じている間だけ外向きに 0.09mm 離して最大 1.6 に。折り（0.42秒）・開き（0.32秒）で紙の半分の白と赤が入れ替わる速さは 0.65/0.6 秒に（a03 最大 8.32）
- **静止**: 煙が浮力不足で止まる・カメラも最後に減速して静止判定（#051）→ 下の「4c. 流体・布」を参照
- **ブーリアン失敗**: 破片の横棒が輪とひし形に重なる（#053）→ 重なる部品を避ける、下見で割れ方を確認
- **Z ファイティング**: 下の段階表示の帯が暗い板と同じ奥行きで重なり、かすれて消える（#100）→ 奥行きをずらす
- **見た目**: 爪が波の内側へ巻き込んで泡に隠れた（#110）／クロスが覆ったとき像の足元が見える・光沢が控えめ（#047）／歯車の接し方が近似（#036）→ 自己評価の弱点として正直に記録
- **映り込み・光**: 映り込みが水面から外れる → 水平線と映す比率を調整（#060。ブラウザ描画の例だが同じ発想）
- **360°（正距円筒）**: 継ぎ目（左端列と右端列の差が、隣り合う列の差と同程度か）と極（最上段・最下段の標準偏差が小さいか）を `python scripts/check360.py equirect.mp4 outdir --times 0,6,11.9` で数値化。実績: 継ぎ目の差 0.44〜0.73 ≦ 隣接列差99%点 0.79〜1.42、極の標準偏差 0.33以下で OK（#042）。静止の誤検出（太陽の上昇が終わり際に遅くなる）にも注意。継ぎ目を中央に回した切り出し（`seam_XXs.png`）と立方体6面（`cube_XXs.png`）で目視
- **ベイク・キャッシュ**: クロス・炎・流体は先にキャッシュを計算してから描く。キャッシュは数GB。ディスクを確認し、書き出し後は消す

## 4b. 作品の型ごとの知見（複数の制作セッションの振り返りから）
**光・単位**（下見で最も多い）
- **単位は最初にメートルで実寸に合わせる**。1単位=1cm のつもりで作ると箱が幅40m になり、面光源 900W では届かず真っ暗（#106 は 22000W、霧の密度 0.045→0.022）。逆にミニチュア（人形6〜8cm）は面光源 26W で色が飛んだ（8／2.2／5W、world 0.35→0.12 #031）。上が白飛びならキーライトを下げる（1400→900W #035）
- **夕日が効かない → まず太陽の高度を疑う**: 高度20°だと向かいの建物の影に通りが全部入っていただけだった。高い太陽で上書きするデバッグ引数（`--sun-debug`）で正常と確認してから調整（#028）
- **明滅は光源の energy を切り替えない**: 0.15⇔1 に切り替えると地面の光の輪ごと明滅した。光源は `smooth(ton, ton+0.4)`、またたきは電球と光の円（面積の小さい物）だけ。直したあと、危ない区間（3.9〜4.7秒）の25コマを540pで連続して描いて測ると最大差 1.78（#028）
- 動く物に `TRACK_TO` するライトは、照明が動く → 動かない空のオブジェクトを狙う
- 風防などの四角い映り込み: 光の板（`visible_camera/diffuse/shadow=False`）を細く、Specular IOR Level 0.22（#026）
- ガラスは Light Path の **Is Shadow Ray** で透明にすると、影で文字盤や床が沈まない。半透明は Mix(Transparent, Principled) を Layer Weight（Facing）で混ぜ、屈折なしにすると軽い（#100: 48 samples で 1.1〜1.7 秒/コマ、transparent_max_bounces 16）
- AgX で色が淡い → 素材の色を濃く、空の光を下げる（0.75→0.45 #044）

**時間の予算**
- **samples の意味は engine ごとに違う**: EEVEE は `taa_render_samples`（#028 は16、#106 は48 で 1.7 秒/コマ）。Cycles は `cycles.samples`
- **屈折の時間は跳ね返り回数が効く**: max/diffuse/glossy/transmission を 16/2/8/14 → 10/1/5/9、24 samples で 3.5→1.5 秒/コマ（書き出し 6.8 分 #053）
- **秒/コマは「重い区間」で測る**（#053 は割れ目の区間 4.2 秒、他は 2.4 秒/コマ）。**最初のコマはシェーダーのコンパイルで 17 秒前後**かかる（平均から除く）
- 各コマで位置を手で置く作りではモーションブラーが効かないので切る（#035）
- 実績の 1080p: #044 は 48 samples＋被写界深度＋モーションブラーで 1.98、#035 は 64 samples でガラスあり 2.62、#045 は 48 samples で 1.96 秒/コマ。ベイクの時間は問題にならない（0.7〜3 秒）
- 12fps のコマ撮り（#031）: `k=floor(f×12/30)` の絵だけ描き、残りは PNG をコピー（描いたのは120枚、513 秒）。同じ絵が続くのは最長3コマ（0.1秒）なので静止判定（0.5秒）に当たらず宣言は不要

**物理（剛体・クロス）は、画像より先に「ベイク専用の probe」を作る**（#045・#044）
- 画像を書かず、ベイクだけ回して「動き始めたコマ」「最終の角度」「`chain_ok`」を done.json に出す（試行に数えない。#045 は8回で連鎖が最後まで届いた）。止まった所と直し方の例: 押し棒が最初のドミノに約2cm届かない → 押す距離 0.95→1.35／押し棒の向きと動く経路の向きが違い素通り → 経路の向きの後ろに置く／1.4倍ずつ大きくするドミノの6枚目が3°しか倒れない → 1.35倍・間隔 0.5h、質量 ∝ h^2.2 で 20° まで倒れる／最後のドミノがシーソーの端に横から寄りかかって止まる → 上から当たる位置へ
- 塔の崩壊（#044）: 摩擦 0.62 では塔が棒のまま倒れ、0.36 では下から曲がるだけ → 0.48。玉の半径 1.5→1.75・速さ 10→14m/s、積み方に ±3cm の不揃いで崩れて散る。**スローは `rigidbody_world.time_scale=0.3`、パーティクルも `settings.timestep=TS/FPS` にしないと速いまま**。ほこりは、ベイク後に各コマの位置を読んで「床の近くで速さが45%以上落ちた」所に出す
- カメラの道筋もベイク結果（いま動き始めた物）から作り、ガウス（σ=14コマ）でならすと、手で付けるより確実
- 剛体の「最初は休止」は、キネマティックで動かす物に触れれば起きる。HINGE は拘束オブジェクトの局所 Z が軸（X に -90° 回すと世界の Y）
- **状態や判断のある作品は、計算部分を Blender に依存しない別ファイル**（python）にして先に通しで確かめる。scene.py からは `sys.path.insert(0, dirname(__file__))` で読む（#041 の cube.py は40シード全部そろうことを確認）

**モデリング・Blender 5.x の API**
- メタボール `ELLIPSOID`（radius 1, threshold 0.6, stiffness 2）は、見える半径が size の約0.43倍しかなく部屋がばらばらに → ×2.3。縮めすぎると殻が崩れる（殻 7〜8%、内腔 kk²）。**回転の軸の向きは下見で確かめる**（Euler Y +0.62 だと心尖が逆向き、-0.62 が正 #100）。メタボール要素や文字の body を毎コマ書き換えるときは `view_layer.update()`
- 庇などの rotation が世界の原点中心に回る → 付け根を原点にして `location` で置く
- 1つのメッシュを共有して色だけ変えるときは `material_slots[0].link='OBJECT'`。`.ttc` フォントは `fonts.load` で読める。札は Blender 内蔵フォントの文字に `TRACK_TO` でカメラを向かせる
- 色の混合は `ShaderNodeMix`（data_type RGBA）。キーフレームは fcurve を触らず毎コマ `keyframe_insert`（5.x の slotted action を避ける。確認はしていない）
- Freestyle と Shader to RGB は Blender 5.2 の EEVEE で動いた。EEVEE の段の境目のざらつきは `use_raytracing=False`・`shadow_filter_radius=0` で消えた（推測）
- 自前のボロノイ分割で破片が抜けたとき、凸包に作り直しても直らなかった。**本当の原因は部品の重なり**。種220に対し破片142は、穴や外側の種の分で正常（#053）
- 爪・曲がり物の向きは「外形の向き」に足す角度で決まる（+0.45rad・曲げ 2.1〜3.0 だと内側に巻いて泡に埋もれた → +1.05rad・曲げ 1.5〜2.2・太さ 0.34→0.4 #110）。Z ファイティングは差を 0.0005 では足りず 0.003 下げた（-1.0005 → -1.003 #100）
- カメラが近くて物が切れる → 距離を足す（9.6→13.6 #041、4.6+4.6E → 4.6+6.6E #035）

**GPU 待ちの記録（制作時間の読み方）**
- 下見（`blender_test.py` 相当）は画像を書かない probe でも GPU の順番を待つ。#045 は1回で 6460 秒待った（ベイクは 0.7〜3 秒）。GPU を使わない probe は待たずに通す道があるとよい（提案）
- 出力を grep や tail で絞ると「gpu wait」の行が消えて待ち時間が記録に残らない。待ち時間は summary の `wait_minutes` に入らない場合がある → 下見の待ち秒は別に記録する
- 制作時間には、利用上限の停止と GPU 待ちが含まれる（#106: 383 分のうち作業は約51分、#053: 615 分はほとんど待ちと停止、#045: 631 分に probe の待ち約2時間と停止）。作業時間の比較では差し引く

## 4c. 流体・布・折り紙（複数の制作セッションの振り返りから）
**煙・炎（Mantaflow）**
- **浮力だけでは煙が止まる**（alpha 0.15、alpha 1.5/beta 3.0 でも止まった）。点の WIND 力場を強さ4にすると約2秒で画面外へ飛ぶ。落ち着いたのは 風 0→0.18→0.28、TURBULENCE 0→0.45→0.8、distance_max 16（#051）
- 最後まで動かす決め手は、**地面に燃え残る火**（円板の FIRE の流れを爆発の25フレーム後から置く）と、**カメラのキーを尺の外（±60フレーム）まで延ばす**こと。最後の10コマの画素差は 4〜5 → 135〜174
- 力場は全ドメインに効く → 焚き火のドメインと火の粉は `effector_weights` の wind/turbulence を 0 にする
- 場面転換（焚き火→爆発）で平均輝度が 47→19 に落ちた → `view_settings.exposure` にキーを打ち、0→−3（0.6秒）・−3→0（0.5秒）でつないだ
- **分割数の下見は本番に近く**: 48/56 は炎がほぼ出ず球形の火球。72/84 にして初めて判断できた。**問題の区間だけ**下見する（`--skip-fire` で爆発だけ: 下見1回 約30分→約6分、GPU 待ち＋ベイク込み）
- ベイク: 焚き火372秒・爆発252秒（72/84）、キャッシュ約8GB。キャッシュを各試行の一時フォルダに置くと掃除で消えて都合が良い。空き RAM は最小 2.19GB で、分割数をこれ以上は上げられなかった。**火の粉の細かいざらつきは直しきれなかった**（a02 でも細かい光の点のまま。自己評価の弱点として報告。推測: Mantaflow のノイズの見え方が大きい）
- 力場は `bpy.ops.object.effector_add(type="WIND")` で作る（`bpy.data.objects.new(name, None).field` は None）。ベイクは `bpy.ops.fluid.bake_all()` を `temp_override(object=dom, active_object=dom)` で呼ぶ
**布（Cloth）**
- **`mass` は頂点1つの質量**: 0.12×約9400頂点で重すぎて風の強さ1100でも動かなかった → 0.01、`air_damping` も比例して 0.35（2.2 だと動かない）。キャッシュは `frame_set` を順に回す（600フレームで約3.5分）
- とがった円すいの耳が布の頂点の間を突き抜けて引っかかった → 丸いメタボール、衝突の厚み 0.012、摩擦 0.1、風を右上50°・最大3500
- ベイク／キャッシュ後に中心座標や強さを log に出す `--probe`（絵なし）を入れると、「動いていない」ことが数秒で分かる（#047 で4回）
**折り紙（#040）**
- 紙は凸多角形の面の集まりにし、面ごとの 4×4 剛体変換だけで動かす（伸び縮みしない）。幾何は Blender から切り離した numpy の `crane.py` にして、共有点のずれ（最大 0.029＝15cm で約2.2mm）と「動く束が最上層か」を普通の Python＋PIL の簡易描画で確かめてから Blender に渡した。**下見の GPU 待ちが 290〜710 秒あるので、Blender の外で詰めるのが最も効いた**
- 手順を2回実行すると、2回目で細かい面の重心の判定がずれて分割がずれる → 1回だけ実行し、最終の細かい面は「各段階でどの粗い面の一部か」で動きを受け継ぐ。中割り折りは剛体のままだと折り返す瞬間に前後の層が約87°開く解しかない（φ の探索範囲を 86° で切ると面が 0.8 離れた）→ 開く→折り返しながら閉じる、の2段（推測: 実物は紙が曲がって開きを小さくしている）
- EEVEE 32 samples・80面＋折り筋の帯548本で 0.7〜0.8 秒/コマ（最初の1コマだけ 11.8 秒）、892コマで 583.7 秒。エリアライト 60W は AgX でも白飛びして赤がピンクに見えた → 16W
**機構・時計（#036）**: 手前のテンプの輪がアンクルを隠した → カメラを真上寄りにし、狙いをガンギ車とアンクルの間に。噛み合いは、受ける側の角度 = β+π+π/N_B −(α_A−β)·N_A/N_B（β は軸間の向き）で位相をそろえると歯が重ならない
**秒/コマ（1080p）**: #047 は 64 samples で約3秒/コマ（31.2分）、#036 は 64 samples（27.4分）、#051 は 48 samples・体積ありで約7.4秒/コマ（a01・a02 とも約89分）。**GPU 待ち**: 下見 #036 570秒・170秒、#051 940秒。試行の待ち #036 a01 690秒（RAM 680・GPU 10）、#051 a01 490秒・a02 420秒
**Blender 5.x**: アクションが層の形式（slotted action）で `action.fcurves` がない場合がある → 補間の変更は `hasattr` で守る

## 4d. 「狙った結果で止まる」物理（検証 T8 サイコロ）
- **probe を総当たりして条件を選ぶ**: 画像を書かないベイク専用の probe は 1 試行 0.04〜0.05 秒。開始姿勢・初速・回転を乱数で 12,406 通り回して（6回に分けて 10 分で収束）、狙いの目（6）・休止時刻・跳ねた回数・テーブル内、を満たす組を選んだ。2500 通り中、上向きが 6 は 399 本（16.0%、出目に偏りなし）、休止は 2061 本、**厳しい条件（休止 5.0〜7.2 秒・跳ね 3 回以上）を満たすのは 1〜8 本**。採用した条件・本数・止まった時刻・最終の上向きの面を `chosen.json` と notes に残す。本番の scene で同じ条件を再計算し、最終位置が probe と一致する（再現性）ことも確かめる
- **`time_scale` を先に決めてから初速を探す**: キネマティックで動かして解放すると初速は引き継がれるが、`time_scale` を変えると初速の意味が変わる（0.3 にして 0.5 m/s でも 5000 本中 4018 本がテーブルから落ちた）
- **止まる時刻が尺の後ろ（7秒以内）に収まる解は少ない**。最後を静かにするには、time_scale・初速の探索範囲を先に絞る。止まるまで 5.57 秒（尺の56%）だった
- **止まったあとのカメラ**: ガウス追従だけだと収束して画素差 0 になる。**止まった後の動き（ゆっくり寄る＋横に滑る・ほこり）を最初から設計に入れる**（a01 は止まった絵が約 2 秒完全に静止 → a02 で 159 コマ以降を再描画）
- **出力パスは絶対パスにする**: Microsoft Store 版の Blender は相対パス（`--out T8_dice/dr`）だと別の場所へ書き、出力が空に見える
- サイコロ: 向かい合う面の和 = 7（+Z=6, -Z=1, +X=3, -X=4, +Y=2, -Y=5）。点はモデリング（つぶした球）、ベベル 6mm
- 数字: Cycles OptiX・32 samples・適応サンプル＋OptiX デノイズ・1080p で 5.6 秒/コマ（最初のコマ 4.9 秒、最大 6.2 秒）、300 コマ 28.0 分、GPU 待ち 0。下見（960×540・16 samples、5 コマ約 10 秒）で構図を 3 回直した（0 秒で物が画面外、世界の縁が見える、木目の縞が細すぎる）。a02 は a01 の 0〜158 コマを流用（カメラ経路が同じ）し、159〜299 コマだけ再描画（13.2 分）
- 上から降りてくる物体の追従カメラは、空オブジェクトを `TRACK_TO` し、経路は probe の結果からガウス（σ14 コマ）でならす
