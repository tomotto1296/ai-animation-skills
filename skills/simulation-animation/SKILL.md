# シミュレーションをアニメーションにする

実績: 物理・粒子・生成・科学系の約40作品。手戻りの多くは「書き出してから分かった数値の問題」だった。**先に数値で確かめる**のが一番効く。

## 初回の確認（自動）
このスキルを初めて使うときは、最初に `python scripts/doctor.py` を実行して、環境が足りているかを確かめる（足りないものと、直し方が表示される。`--fix` を付けると、直せるもの（npm install など）はその場で直す）。ユーザーに手で準備させる前に、まずこれを試す。

## 1. 進め方
1. **計算部分を描画から分ける**: DOM・canvas を使わない `sim.js`（または numpy の関数）にして、`simulate(seed, frames)` が毎コマの状態を返す形にする。描画は別ファイル
2. **node（または numpy）だけで全尺を回して数字を見る** → `scripts/sim_check_template.mjs`（シード総当たり・山の数・全滅・NaN）。ブラウザの下見より速く、見間違い（「点が偏っている」）も数値で否定できる
   - main.js しかないときは、import 行と `startWork(...)` 以降を消して `eval` すれば node で回せる
3. **パラメータの当たりは記憶でなく小さな試算で**: 例）Gray-Scott は覚えていたプリセットが全部外れた（F=0.058 k=0.065 は斑点のまま、F=0.029 k=0.057 の迷路は模様が消える）。numpy の 200×120 で候補を一覧（約25秒）して決めた
4. 数字で決めてから描画の下見（数コマ、1080p の等倍）→ 本番。重い作品だけ draft（540p）で全尺を下見
5. 「出来上がりを決める数字」を決めておく: 面積比、輪郭の折れ点数、形のずれ、最小車間、最大めり込み、NaN の有無、全滅しないか、山の時刻（見せ場の時刻に合うか）、最後の状態

**状態を持つ作品でも stateless で書き出す（検証 T7）**: シミュレーションを setup で全コマ計算して**表にし**、`frame(i)` は表を引くだけにする。下見も任意のコマが即描ける（状態を持つ作品の「0から全部計算」が要らない）。流れ・運搬系の検査指標（納品数の推移、止まっている個体の割合＝1秒前との位置差が小さい個体の割合、60pxマスの最大密度、道の芯の濃度の推移）の見本は `scripts/check_sim_flow_example.mjs`。**採用基準を数値で先に決め**、シード 1〜40 の総当たり（5秒）で満たすものを選ぶ（T7: 40シード中4つ、シード2を採用。納品数は 16〜46 と大きく違った）。
- **濃度の表示写像が見た目を決める**: 道の太り方は、濃度をそのまま明るさにせず `1-exp(-v/2)` のような飽和する写像にすると見せ場の時刻に出る
- **10秒に収める時間圧縮**: 実際の速度では10秒で終わらない → 速度（280px/s）・巣と餌の距離（700px）・初期の数（36匹）・発生率（38/s）を、見せ場が 4〜8 秒に来るように決める
- 動きが続くかの検査は、「1秒前との位置差が 25px 未満の個体の割合」が有効（最大 0.03＝固まりなし）。背景の動きがなく個体が少ない設計は、静止判定に当たりやすい（推測）。T7 は max_frame_delta が 0.07 と小さく、QC は PASS したが余裕は小さい

## 2. 乱数とシード
- 乱数は**シード固定**（`mulberry32`）。同じ入力で同じ映像になること
- 候補シードを数値で選ぶ: 例）捕食者・被食者で、シード 1〜40 のうち 23 でキツネが全滅 → 全尺の数値を見て採用シードを決めた（#096。シード29）。子をランダムな親の近くに生むと全体が1か所に固まるので、散らした巣穴（8か所）から生ませた
- 規則で動く作品の配置は**目算せず総当たり**: グライダー銃5台の間隔・ずらしは、幾何の見積もりで2回干渉した。間隔 d・ずらし t を総当たりして 800 世代干渉しない d=13〜18 を得た（200〜240世代の検査では短すぎて誤って合格にした。**検査の長さは本番の長さに**）

## 3. パターン別の知見
**柔らかい物・変形（ソフトボディ）**: 硬すぎると変形が見えない（面積比最小 0.988）、柔らかすぎると輪郭が折れる（折れ最大 8〜10 点）。a03 で面積比 0.998〜1.000・折れ1〜3点・階段へのめり込み 0px・NaN なし。#046 は a01 硬すぎ → a02 柔らかすぎ → a03 で収束した。**指標（面積比・折れ点数・めり込み）を先に決め、数値で追い込む**と回数が減る
**流体・熱・対流**: 温度に上限がないと速度が暴れ、色が一様に散って「消えた」ように見える（NaN ではない）→ 温度は目標（≤1）へ緩和、速さに上限（110 格子/秒）。滴が領域の約0.15%しかないなら注入量を約8倍にしないと見えない
**溶岩ランプ（対流する塊）**: 「高さで決まる目標温度へ近づける」だと中ほどに安定点ができ、全部が浮いたまま止まる → 底でだけ温め、ほかでは冷やす（ヒステリシス）。引き合いと熱の共有は1つの塊になるので外す。事前に24秒動かして周期をずらす
**煙・炎**: 浮力だけでは止まる → 風 0.18〜0.28・乱流 0.45〜0.8（距離上限16）に、**地面に燃え残る火**と、カメラのキーを尺の外まで延ばす（強い風は約2秒で煙が画面外へ。詳細は Skill `blender-headless` 4c）。（火の粉の細かいざらつきは #051 では直しきれなかった。Mantaflow のノイズの見え方が大きいと推測）
**パターン形成（反応拡散）**: 縞＝拡散の異方性（Dx1.7・Dy0.5）、迷路＝同じ F・k で拡散の距離0.45倍。縞のあとに等方の条件へ変えても縞が残る
**成長（差分成長・結晶）**: 一律の確率で点を足すと8秒で上限（14,000）に達して詰まる → 足す確率を `0.045×max(0, 1−近傍数/10)` にして空きのある所だけで成長。1フレーム3反復・移動上限3px・上限23,000 で 26 秒間もつ。node で先に回して決めた
**付着・成長の速さを時間割に合わせる（DLA・霜・雷）**: 粒子を一様に生むと霜が急に画面を埋め、空き場所がなくなって成長が止まった（15,473→37,892 で停止 #075）。**1コマの付着数に上限**を設け、目標曲線（nSeed + 11000·u^1.2）から毎コマ計算する。粒子は霜から離れた 8×8 ブロックでだけ生み、雷の先駆放電は粒子の80%を先端のまわり（σ=26）で生み、上限46/コマ
**貪欲法のストリングアート**: 「糸1本で減らす量」を、実際に描く線の濃さに合わせる（0.2 だと 532 往復で止まり灰色一色。0.045＝幅1.25px・不透明度0.17の線が1マスを暗くする量で 2,483 往復）。明るい背景を暗さ0に写像し、目・眉・鼻・口に重み 2.5、顔を 1.45 倍にして顔として読めた
**波の干渉・光の網目**: 長い波1本が支配すると斜めの格子になる → 全方向に11本、振幅は波長に比例、速さは √波長。波紋の波長 11→17 格子でエイリアシングも消えた
**群れ（ボイド）とカメラ**: ねぐらを追うカメラは群れの実際の位置からずれて、群れが画面の端から出る → 群れの重心を時定数0.8秒で追う（状態の一部にすれば決定的なまま）
**水面の映り込み**: 空の高さ（約400px）が水面の深さ（320px）より大きいと映り込みが画面外に出る → 水平線を上げ、反転の縦比を調整（760→640、1.4）
**オーロラ・光のカーテン**: 折れの強調 1/max(dX/ds, 0.18) が強すぎるとサーチライトの筋に見える → 0.45・上限2.2
**manim**: 画像を書かずに `--count` で総コマ数を出し、duration をそれに合わせる（837コマ＝27.9秒）。`from manim import *` は `OUT`（方向ベクトルの定数）を持ち込み、出力先の変数を上書きする → 出力先は `OUTDIR` などの名前に
**粒子の群れ**: 塊のまま飛ぶ・渦が三日月になる → 粒ごとの抗力（0.9〜5.4）・風の受け方（0.55〜1.45）・渦の半径のずれ（±150）で散らす。背景の粒まで渦に捕まると輪が残るので、背景は渦の影響から外す
**交通・追従モデル**: 最適速度モデルの感度 a=1.0 で車間が負（最小 0.03m、すり抜け）→ a=2.0（最小 3.7m）。node で数値を確かめて決めた
**振り子・揺れ**: 斜めの視点（ピッチ 0.62rad）では手前への振れが見えない → 0.95rad の見下ろし・振れ幅 0.32→0.4rad。放す前の静止はカメラをゆっくり回して静止判定を避けた
**砂・粉体**: 漏斗の傾きが砂の安息角（45°）と同じだと壁に砂が残って落ちきらない → 約66°に急にして、楕円の首側の肩も除いた（#052）
**群衆**: 壁の反発が強いと、誰も通路に入れない → 壁の力を近距離だけにする（A 3・B 0.05・0.8m で打ち切り #056）
**進化・世代**: 第1世代の最速個体はほぼ動かず静止判定に当たりそう → 見せる世代を絞る（1・20・45・80 の4つ）、背景（雲）を流す（#095）
**ループ作品**: frame 0 と最終コマの PNG の MD5 が一致することを確かめる。動く部分の周期は、1周期を割り切る値（1・1.5・2・3・6秒）。段ごとに重ねる効果（ガラスの反射など）は継ぎ目で切れ目になるので入れない
**深いズーム（フラクタル）**: 32ビット小数で 10¹² 倍は崩れる → 摂動法（参照点は周期点のミニブロ中心、各画素はずれ δ だけを32ビット、`|Z+δ|<|δ|` で参照軌道の先頭へ乗り換え）。望む大きさの目標は先に高精度（mpmath 60桁）で探す
**物理の説明ラベル**: 向き（外積など）はシェーダー・物理計算と**同じ式**で出す

## 4. 描いた後の確認
- 最後の区間は「表示を全部止めたら何が動くか」で確かめる（経過時間の数字だけが動いていて、実は静止していることがある。0.5秒以上止まると QC の静止になる）
- QC の物差しは Skill `animation-qc-selfreview`。ブラウザ描画は Skill `browser-frame-render`
- 数字は記録に残す（シード、採用パラメータ、検査の数値）。**直し方は具体的な数値つきで**

## 5. 性能
- 重い作品は先に draft（540p・粒子数削減）で全尺。本番は final を1回
- 状態を持つ作品は並列化できない（分割すると結果が変わる）。下見でも後半のコマは 0 から計算し直しで遅い
- GPU を使う書き出しは同時に1件（VRAM に収める）。直列で 6.26 秒/コマ（4K）は並列化しても重い → 解像度を下げる／尺を縮める
